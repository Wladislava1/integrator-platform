# Паспорт проекта — Integrator Platform (Связь ID)

## Название

**Integrator Platform** — платформа-интегратор с единым входом **Связь ID**.

## Происхождение

Собственный учебный проект, создаваемый с нуля в рамках курса программной инженерии.

## Назначение и решаемая проблема

Сейчас у команд часто появляется несколько внутренних продуктов, у каждого — свой вход. Пользователь путается в учётках, а разработчики дублируют регистрацию.  
**Связь ID** даёт одну учётную запись физического лица и точку, куда позже подключаются продукты через API. Integrator Platform выступает каталогом и «склейкой» этих продуктов.

## Целевые пользователи и роли

| Роль | Описание |
|------|----------|
| Физическое лицо | Регистрируется и входит через Связь ID, видит каталог, управляет профилем и темой |
| Внешняя система (продукт) | Планируется: подключается к платформе по API и использует единый вход (заглушки в Lab 1) |

Требование курса «≥2 роли **или** 1 роль + внешняя система» закрывается связкой «физлицо + будущие внешние продукты».

## Три основные функции (сейчас)

1. Регистрация и вход физического лица (email + пароль, JWT).
2. Просмотр каталога продуктов (слоты-заглушки под будущие карточки).
3. Профиль и настройки темы (светлая / тёмная).

### Точки входа

- UI: `src/app/page.tsx` → редирект на `/login` или `/catalog`
- Dev-сервер: `npm run dev` (порт 3000)
- Auth API: `/api/auth/*`, профиль `/api/profile`, тема `/api/settings/theme`

### Внешние зависимости и сервисы

- В Lab 1 внешние сервисы не требуются.
- PostgreSQL запланирован; схема готова, подключение не выполняется.

### Хранение данных

- Сейчас: локальный JSON-файл `.data/users.json`.
- Далее: таблицы `users`, `sessions`, `products`, `user_settings` (см. schema.sql).

### Конфигурация

- `AUTH_SECRET` — секрет JWT (см. `.env.example`).
- Остальные настройки — через код и переменные окружения Next.js.
