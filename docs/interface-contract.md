# Контракт операции «Связать аккаунт Потеряшек»

Версия 1.0, 2026-11-24.

## Операция

`POST /api/products/poteryashki/link`

Связывает уже существующий аккаунт тестового продукта «Потеряшки» с человеком, который вошёл в Связь ID. Если почта и пароль Потеряшек верные, вызывающая сторона получает адрес, по которому этот человек сразу открывает каталог объявлений Потеряшек.

Реализация: `src/app/api/products/poteryashki/link/route.ts`. Проверка тела запроса: `productLoginSchema` в `src/lib/validation.ts`. Вызов продукта: `linkLostPets` в `src/lib/lostPets.ts`.

Операция реализована.

## Связь со сценарием

Сценарий US-4, требование FR-4.

Человек уже вошёл в Связь ID, открыл каталог и на карточке «Потеряшки» ответил «Да» на вопрос «У вас уже есть аккаунт в „Потеряшки“?». Эта операция как раз проводит переход в уже существующий аккаунт продукта и новый аккаунт Потеряшек не создаёт.

Тестовый продукт из US-9 и FR-9 здесь — отдельное приложение «Потеряшки».

## Кто вызывает и как

Вызов делает страница каталога в браузере человека, уже вошедшего в Связь ID. Запрос уходит на тот же адрес, где открыта платформа.

```http
POST /api/products/poteryashki/link HTTP/1.1
Host: localhost:3000
Content-Type: application/json
Cookie: svyaz_id_token=<jwt сессии Связь ID>

{"email":"petr.pets@example.com","password":"Pets-26"}
```

Cookie `svyaz_id_token` браузер отправляет сам: она httpOnly, ставится при входе и живёт 7 дней. В тело запроса её копировать не нужно. Пароль в теле — пароль Потеряшек, не пароль Связь ID. Почта в теле — почта аккаунта Потеряшек; она может отличаться от почты в Связь ID.

## Входные данные

Тело — JSON-объект.

| Поле | Тип | Обязательно | Допустимые значения |
|------|-----|-------------|---------------------|
| `email` | строка | да | Почта существующего пользователя Потеряшек. Пробелы по краям отбрасываются. Строка должна быть корректным email |
| `password` | строка | да | Пароль этого пользователя Потеряшек. Пустая строка не принимается |

Других полей операция не читает.

## Условия вызова

1. У человека есть действующая сессия Связь ID. Без cookie `svyaz_id_token` или с просроченной сессией ответ `401` и тело `{ "error": "Требуется вход" }`. Связка не создаётся.
2. Приложение «Потеряшки» запущено и доступно платформе.
3. В Потеряшках уже есть пользователь с указанной почтой. Эта операция его не регистрирует.

## Успешный результат

Код `200`. Тело:

```json
{
  "redirectUrl": "http://localhost:5173/svyaz?code=<код перехода>"
}
```

`redirectUrl` — адрес входа в Потеряшки. Код в адресе новый при каждом успешном вызове и действует 2 минуты. Каталог открывает этот адрес в новой вкладке. Человек попадает в каталог объявлений Потеряшек под тем аккаунтом, чьи почту и пароль прислали. Форма входа Потеряшек не показывается.

Что сохраняется при успехе:

- в пользователе Потеряшек записывается идентификатор человека из Связь ID (`users.id`);
- если этот идентификатор раньше стоял у другого пользователя Потеряшек, оттуда он снимается;
- в таблице `product_links` платформы запоминается почта Потеряшек для этого человека и продукта `poteryashki`.

В ответе нет пароля, хеша пароля и профиля.

## Характерная ошибка

Неверная почта или неверный пароль Потеряшек.

Код `400`. Тело:

```json
{
  "error": "Неверный email или пароль в Потеряшках"
}
```

Поля `redirectUrl` нет. Новая вкладка не открывается. Идентификатор Связь ID в Потеряшки не записывается, строка в `product_links` не меняется.

Та же форма ответа, код `400`, бывает при пустом или некорректном теле. Текст тогда другой: `Некорректный email` или `Введите пароль`. Для проверки контракта ниже взята ошибка неверного пароля.

## Пример 1. Успешный вызов

Человек в Связь ID: Иванова Мария Сергеевна, `maria.ivanova@example.com`. Сессия уже есть, cookie `svyaz_id_token` действует.

В Потеряшках уже есть пользователь `petr.pets@example.com` с паролем `Pets-26`.

Запрос:

```json
{
  "email": "petr.pets@example.com",
  "password": "Pets-26"
}
```

Ожидаемый ответ: `200` и `redirectUrl` вида `http://localhost:5173/svyaz?code=...`. Каталог открывает эту ссылку в новой вкладке на каталоге объявлений. В Потеряшках открыт `petr.pets@example.com`, и у этой учётки записан идентификатор Ивановой из Связь ID.

## Пример 2. Неверный пароль

Та же сессия Ивановой Марии Сергеевны. В Потеряшках пользователь `petr.pets@example.com` есть, но пароль в запросе не его.

Запрос:

```json
{
  "email": "petr.pets@example.com",
  "password": "Wrong-00"
}
```

Ожидаемый ответ: `400` и тело `{ "error": "Неверный email или пароль в Потеряшках" }`. Адреса перехода нет. Учётка `petr.pets@example.com` остаётся без идентификатора Ивановой.
